## GLOSSARY

A *Glossary* is a list of concepts, words or acronyms with brief explanations
of how they are used and understood in a context.


| *Term* | *Explanation*  |
| ---    | ---            |
| *Requirement*           | Formalized (written) and with all stakeholders agreed *expectations* that must be satisfied in order to be accepted (see also *Acceptance Criteria*). Requirements from the user's perspective can be written as: *use cases*, graphically as *use case diagram* or informally as *user stories*. Requirements from the system's perspective are written as *functional requirements (FR)* and *non-functional requirements (NFR)*. |
| *Acceptance Criteria*   | List of demonstratable criteria associated with a *requirement* (a *user story* or a *use case*) that declares when the *requirement* has been completed. An alternative term is *Definition-of-Done (DoD)*. |
| *Requirement Analysis*  | Planning process in software engineering that rationalizes (unify ideas, proposals, comments, terminology), structures and formalizes (turns into written specifications) requirements for a product development, see [*see*](https://en.wikipedia.org/wiki/Requirements_analysis). |
| *Stakeholder*           | Individuals, group, or organization involved in decision making, investment or oversigh who are not primary users of the system. Examples are owners, decision makers, investors, authorities, etc. |
| *Actor*                 | Anything outside that interacts with the system. For example: a user, a role, an outside system or an external service. |
| *Role*                  | Defines a set of responsibilities, permissions, behaviors or properties as an abstraction of individual users. For example: customer, guest, staff, manager, system administrator.  |
| *Persona*               | Person with a name and associated properties used to clarify requirements. For example: *Angela* is a 72 year old woman who does not use a mobile phone. |
| *Use Case (UC)*         | Requirement that describes specific steps, actions and interactions between an *actor* and the system. |
| *Use Case Diagram*      | Graphical representation of requirements showing *actors* and *use case names*. |
| *User Story (US)*       | Brief, informal description of *one* specific requirement or feature from the perspective of a role.<br>- Format: `<ID>: As a <ROLE>, I want to <ACTION/GOAL> so that <BENEFIT>`.<br>- Example: US#0010: As a guest, I want to register so that I can rent a car. |
| *Functional Requirement (FR)*      | Requirement that describes of *one* specific *technical function* the system must provide.<br>- Format: `<ID>: The system <MUST\|SHOULD> <PERFORM-FUNCTION>`.<br>- Example: FR#0010: The system must print the list of products. |
| *Non-Functional Requirement (NFR)* | Requirement that describes of *one* specific *non-technical* requirement, the system must meet.<br>- Format: `<ID>: The system <MUST\|SHOULD> <MEET-NFR>`.<br>- Example: NFR#0010: The system must store at least 10,000 products. |
| *Product Manager* or *Product Owner (PO)* | *Role* that is responsible for *"managing the product"* of defining product features (*requirements* and *acceptance criteria*) and their delivery time lines. |
| *Product Roadmap*       | Time-line (x-axis in months or quarters) showing when features are made available for a product.<br>Example: [*Java Product Roadmap*](https://en.wikipedia.org/wiki/Java_version_history) with releases over the years and also extending out into the future. |
| *Project Manager*       | *Role* that is responsible for *"managing the project"* in all aspecpts such as people (hiring), budget, setting goals (milestones) and delivering goals. |
| *Business Process (BP)* | Structured, repeatable, long-lasting (weeks, months, years) sequence of activities performed by people, systems, or organizations to achieve a specific business goal. Example: Customer-Registration process. |
| *Business Object (BO)*  | Data entity (typically a database record) that represents a collection of information that the system tracks and manages. Example: Customer-Registration record. |
| --- | --- |
